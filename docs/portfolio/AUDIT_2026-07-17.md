## Existing information architecture

Before this work, there was no `/admin/portfolio` route. The public home page
hard-coded project cards and read milestone detail from
`src/data/roadmap.json`. `/admin/improvements` existed as an admin-only queue
backed by the `sevaro-improvement-queue-api` Lambda and the
`sevaro-improvement-queue` DynamoDB table.

The resulting boundaries are:

| Surface | Purpose | Persistence |
|---|---|---|
| `/` | Public/project showcase cards and legacy milestone drawer | Hard-coded JSX plus `src/data/roadmap.json` |
| `/admin/portfolio` | Portfolio-level project source of truth | `src/data/portfolio.json` |
| `/admin/improvements` | Executable improvement/prompt queue | DynamoDB through Lambda; optional link to a portfolio project |
| Private `memory/people` | Private professional memory and sensitive action queues | Existing private location, not this repository |

## Improvement-queue findings

- Primary key remains `(repoName, promptId)`.
- Existing status values are `pending`, `in-progress`, `completed`, and
  `deferred`; priorities are `P1`, `P2`, and `P3`.
- The former repository selector was a small hard-coded list and had no project
  relationship.
- `parentProjectId` is now optional and backwards compatible. A legacy record
  can link through a declared `repoAliases` value only when exactly one project
  matches.
- Unknown or invalid links are shown as `Unlinked`; they are never guessed.

Live DynamoDB rows were not read or changed. Therefore production duplicate
records, missing ownership, and orphan counts remain unknown until an
authenticated read-only export is authorized and available.
